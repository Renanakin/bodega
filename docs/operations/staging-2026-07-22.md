### 2.1 Único fallo: `warehouses / reject_duplicate_name`

**Esperado:** HTTP 422 al crear bodega con `name` duplicado.
**Obtenido:** HTTP **409** con cuerpo:
```json
{"detail": {
  "code": "duplicate_warehouse_name",
  "message": "Warehouse name '...' already exists.",
  "extra": {"field": "name", "value": "..."}
}}
```

**Causa:** la batería (escrita antes de C1.1) esperaba 422 por compatibilidad
con el comportamiento legacy. **El fix de C1.1 mejoró el comportamiento
a 409** que es el código HTTP correcto para "conflicto con recurso
existente" (RFC 7231 §6.5.8).

**Acción:** actualizar `bateria_e2e_demo.py` para esperar 409. **No
bloqueante para go-live** porque es una mejora, no una regresión.

## 6. Lecciones aprendidas

- **`docker_default` vs `bodega-obs`:** el stack de observabilidad usa una
  red propia (`bodega-obs`). El API vive en `docker_default`. Hay que
  hacer `docker network connect` para que Prometheus scrapee la API.
  Fix: agregar `docker_default` al `compose.observability.yml` en C5.

- **Variables de Alertmanager:** `${VAR}` se expande con env vacío, lo
  que rompe la URL. Hay que poner URLs literales o defaults que sean
  parseables como URL.

- **TypeScript en archivos .js:** un edit accidental a `useReviewMvpData.js`
  con anotaciones TS rompió el build de Vite. La detección (TS opcional
  chaining) no es un syntax error en runtime, pero sí en build.

- **Alembic + BD con datos legacy:** la BD tenía tablas pre-Alembic. La
  solución limpia es `DROP DATABASE` y dejar que alembic cree todo.
  Stamp head no funcionó porque internamente hace create_all.
